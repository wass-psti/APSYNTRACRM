## Contract

No mutable current-price pointer or implicit newest-FX selection; a later signed orchestration must explicitly bind the chosen snapshot and source revision.

Persistence serializes per material (not table-wide), locks existing pricing cells, and validates the authoritative state again in READ COMMITTED before calculating with B.1. Read-only live catalog inspection confirmed both item FKs are non-deferrable, and the original public columns have number/dropdown types with observed JSON number/string storage respectively. Recheck exact production dependency definitions before activation. Concurrent changes to board/column metadata or lock inversion may require a transactional retry; no change to existing writers or lock policies is made. The candidate only writes its new history table. A calling transaction can capture a new B.2 FX snapshot, modify source values through established writers, and persist pricing as one unit; failure rolls back all those writes. Legacy snapshots must still match both rate values and revisions even if the caller reads a fresh expected state. Provider-reported snapshots remain independent of legacy cells; provider verification is still deferred.

Missing/invalid source cells or unselected FX produce diagnostic versions with no fabricated authoritative cost; unknown source remains partial per B.1. Exact historical inputs and calculated decimal strings are retained. Historical read is by workspace/material/version identity; hard delete/archive of a material is not blocked by history. No RLS or authorization expansion; future signed adapter must reuse existing commercial scope. No gradient descent, training loops or model dependencies.
