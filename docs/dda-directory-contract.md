# DDA reporting directory — CP-DDA-FE-03A

DDA's operational department hierarchy and personnel assignments are workspace-scoped and seeded from reviewed AGT source identities during initial schema activation. Existing source IDs are retained. DDA does not write AGT classification history, CRM profiles, TimeTracker assignments, memberships, or roles.

The snapshot exposes unassigned existing workforce identities and active CRM members with valid display names. The operator explicitly selects a reporting department; new source IDs and fabricated employee accounts are rejected. Existing DDA assignments and display labels can be edited without changing source systems. Top-level departments and one level of units are supported. Personnel transfers affect future activities; saved activities retain their original department ID. Directory commands use the existing revision, terminal receipt and event mechanism.

This is an application-specific directory, not a global HR master-data editor. Source synchronization after initial activation is explicit: new eligible identities appear as candidates, and existing DDA assignments are not silently overwritten by a later source reclassification. The DDA-only reporting fields include department abbreviation, employee ID, position, company and a single designated supervisor per department/unit. Unknown values remain blank rather than being invented or copied from the reference demo. The employee ID is optional until reviewed, but unique within a workspace when present. Supervisor replacement and transfer are serialized with the existing command receipt; designation does not grant application authority. Department filters include immediate units, using the current hierarchy and original activity department ID. The directory search covers assigned and unassigned identities, employee ID, position and company, without additional backend calls. Department and personnel activity summaries include former contributors based on recorded activity department. Source deactivation and physical removal of historical organizational units remain outside this increment. The production release switch remains off. The SQL candidate has not been applied to production.
