## Delivered reproducible acceptance

`node scripts/pdl-aps-native-02-readiness.mjs`

The script makes **GET and OPTIONS only**; validates real public-origin CORS and unsigned administrator denial; optionally accepts two existing, independently authenticated Supabase Auth JWTs **via the Mac's process environment**, not source, chat, URLs, disk output, or Git; checks `/v1/admin/session` for distinct authorized actor IDs; compares both independent signed reservation lists and the target persisted reservation's booking/payment statuses and version; and reports only aggregate counters and acceptance states. It does not output actor IDs, tokens, PII, receipt media or payment details. No customer record is generated by this script.

To enable genuine live signed acceptance, authorized operators must establish two separate real Supabase Auth sessions using the **existing** Paseo administrator membership directory. Supply short-lived tokens only through a private terminal environment, then run:

```sh
PDL_ACCEPT_ADMIN_A_JWT='[secure runtime token A]' \
PDL_ACCEPT_ADMIN_B_JWT='[secure runtime token B]' \
PDL_ACCEPT_RESERVATION_ID='[existing approved UUID]' \
node scripts/pdl-aps-native-02-readiness.mjs
```

The command exits **2 intentionally**, even if both sessions read the same reservation; this is a read-only preflight, not authorization for financial activation. The use of placeholder strings above is documentation, not an assertion that tokens or reservations exist.
