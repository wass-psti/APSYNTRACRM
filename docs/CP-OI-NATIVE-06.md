# CP-OI-NATIVE-06 — Advanced search and bulk operations

## Scope
Original blueprint: multi-field search, amount range filters, 25-row pagination, export, batch status/company/industry/expenses updates and archive. Reuse CP05A operational registry and current mutation RPCs. No production schema or authorization changes.

## Implementation
All Order Intake views retrieve complete available registry pages; Search, All Orders and Archived display 25 rows per page. Search includes PO, client, account manager, company, industry, historical client evidence, source/confirmation/file references and notes. Structured fiscal year, date, status, currency, company, industry, manager, record type and exact-decimal amount range filters; explicit amount sorting groups by currency. No currency conversion. CSV exports all matching rows, preserves source identifiers, historical financial basis and exact decimal strings; spreadsheet formula-like text neutralized. Selection supports individual rows, page and all matching records, retained across pages and cleared on filter/section changes or explicit refresh. Partial/error/busy data cannot start a batch or export. Existing stored structured preferences remain unchanged; new search filters are URL-addressable.

Bulk status, archive and restore work with both operational historical and native orders. Native active order detail patches update company, industry and/or expenses via the existing revision-aware RPC. Expenses require an explicit currency and skip mismatches; blank inputs leave values unchanged. Historical company/industry/expenses are source values and are not edited by this checkpoint. No additional role restrictions; existing lifecycle terminal rules retained. Sequential independent transactions with exact readback; no claim of all-or-nothing batch atomicity. Skips and unconfirmed writes are reported per order; first unconfirmed write stops later attempts, no automatic replay. Closing the confirmation or leaving scope stops subsequent attempts, not any already in-flight transaction. Refresh reconciles active/archive registry; reports retained in current application session. No new training, gradient descent or model updates.
