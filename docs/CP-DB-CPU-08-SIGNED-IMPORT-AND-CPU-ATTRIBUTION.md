### `wm_list_boards`

A read-only representative plan of the visible-board/item-count portion (with the caller workspace/admin values resolved outside that plan) returned 252 boards and 14,380 active items. The aggregation completed in **9.867 ms**, with 763 shared-buffer hits, zero shared-buffer reads, and an index-only scan using `work_board_items_active_board_count_idx` (252 loops; 77 heap fetches). The `current_workspace_id()` helper separately measured 0.166 ms for the representative account.

This shows that the core board/item aggregation is indexed and fast at the inspected dataset size. The high cumulative RPC wall time is not, by itself, evidence that this query is consuming equivalent CPU. API/pool wait and the full authenticated RPC path remain separate attribution questions.

### `wm_import_board_wizard_extended_atomic`

The importer has the highest cumulative per-call execution time among the inspected application RPCs and substantial cumulative buffer activity. The prior CP-08 snapshot showed 827 calls; the runtime continuation snapshot showed 828 calls, 1,716,588.414 ms total execution, 2,073.174 ms mean, 7,774.337 ms max, 45,548,995 shared hits, and 1,822 shared reads. The single signed QA request was 298 ms at the Edge origin; the cumulative SQL mean must not be mistaken for that request's individual execution time. The one-call counter increase is consistent with the audited import, but the available aggregate statistics do not isolate its SQL CPU cost. The six unrelated import requests remain excluded from QA acceptance.

### Measurement limits

- `pg_stat_statements.track = top`;
- `track_functions = none`;
- `track_io_timing = off`;
- `pg_stat_kcache` is not installed.

Consequently, the database exposes top-level elapsed execution and buffer activity, but not per-function CPU time or nested PL/pgSQL CPU attribution. The privileged Supabase Metrics API was not accessed because it requires a project secret key; no secret was retrieved. No settings or statistics were changed to enable more intrusive profiling.
