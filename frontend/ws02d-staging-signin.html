APSYNTRA · Staging-only invitation acceptance

This tool uses only the isolated staging Supabase project. It is not the production CRM sign-in. Each account holder can use their own device; do not share credentials or session tokens. Credentials and signed tokens remain in the current browser tab's memory only; close the tab to clear them. Use a private window on a trusted computer.

Two independent live staging sessions are required for server-side onboarding, but can be established on separate devices. Email delivery and workspace permissions are not altered by signing in. Use password sign-in when the account holder has their staging password; it does not send email. OTP email requests are shared across both account slots and have a persistent client-side cooldown to prevent duplicate sends. A provider HTTP 429 increases the cooldown; the page never retries automatically and honors Retry-After when supplied. Numeric OTP requires the staging Supabase Authentication → Email Templates → Magic Link template to include {{ .Token }} instead of {{ .ConfirmationURL }}. Never paste passwords, verification codes, access tokens, or invitation tokens into chat. No production endpoint is used. Email submission does not prove inbox receipt.
